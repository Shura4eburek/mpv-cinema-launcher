# Руководство для разработчиков и AI-ассистентов (AI Developer Guide)

Данный документ содержит полное описание архитектуры, ключевых модулей, протоколов интеграции и типичных подводных камней проекта **mpv-cinema-launcher**. Предназначен для разработчиков и будущих LLM/AI-ассистентов для быстрого погружения в кодовую базу.

---

## 1. Назначение проекта
Проект объединяет в себе:
1. **Интерактивный медиа-клиент:** Поиск фильмов и сериалов, выбор озвучки/студии перевода, выбор качества потока (`1080p`, `720p` и т.д.) с постерами и метаданными.
2. **HLS-парсер и обходчик защиты:** Скраппинг CDN-потоков `.m3u8` с сайтов на базе HDRezka с прохождением JavaScript / PoW защиты (Anubis) и обработкой AJAX-запросов плеера.
3. **Продвинутый видеолаунчер mpv:** Запуск плеера `mpv` с преднастроенными профилями апскейла (нейросеть `FSRCNNX x16`, `Anime4K`, `KrigBilateral`), цветокоррекцией и плавной интерполяцией кадров под герцовку монитора (60/144/165/240 Гц).

## 3. Архитектура и ключевые модули

### 3.0. Источники (`sources.py`, `kinogo.py`)
* **Порядок:** KinoGo основной, HDRezka запасной. `sources.py` общий для приложения и CLI. Адрес KinoGo хранится в настройке `kinogo_url`.
* **Поиск и страница:** обычные запросы, селекторы `#dle-content article.shortStory` и `article.fullStory`.
* **Узлы качества:** соединение с узлом ждём не дольше 1,5 с и после `ConnectTimeout` не повторяем: мёртвый узел раньше задерживал шаг «Проверяем качество» на 8,8 с. Мгновенный обрыв или отказ соединения, HTTP-ошибка и `ReadTimeout` повторяются один раз: иначе разовый сбой прятал бы 1080p у фильма.
* **Поток:** `capture_stream` открывает фильм в Chrome, кликает внутри фрейма `cinemar.cc` и читает `hls*.m3u8` из `performance` внутри фрейма. Журнал сети драйвера кросс-доменные фреймы не видит. Кликать вне фрейма нельзя: поверх страницы лежит рекламный фрейм, и клик уводит на другой фильм.
* **Настоящий 1080p:** плеер раздаёт поток через `cfnd`, где `1080.mp4` на деле 720p. `build_streams` заменяет хост на `atlas.host.cinemap.cc` без подписи; порядок адресов: проверенный узел → `atlas` → `cfnd`. `atlas` направляет каждый файл на его постоянный узел. Если узел варианта не отвечает, вариант скрывается: на `cfnd` под тем же именем другое качество.
* **Подписи:** определяются по ширине, потому что кадр широкоэкранного фильма ниже 1080 строк (1920×800).
* **Озвучки:** API плеера их не отдаёт (`audiotracks` пуст), но в `#player` есть скрытый список кнопок. `capture_stream` читает его и переключает озвучку кликом; идентификатор озвучки — её название.
* **Маскировка браузера не применяется.** Если сайт начнёт блокировать автоматизацию, должен сработать запасной источник.

Зеркала KinoGo: `kinogo.DEFAULT_MIRRORS`. Следующее пробуется только при недоступности сайта; пустая выдача считается ответом. Первым идёт зеркало, ответившее последним, затем адрес из настроек. Полный путь до потока прошли только `uakinogo.io`, `.org` и `.tv`; остальные добавлены по просьбе пользователя и на момент добавления отвечали 403 от Cloudflare. Обходить проверку нельзя. Экран «Настройки → Проверить зеркала» (`mirror_check.py`, `MirrorCheck.svelte`) проверяет только поиск, без браузера. У зеркал две вёрстки, селекторы в начале `kinogo.py`.

### 3.1. HDRezka: скраппинг (`scraper.py`)
* **Пул зеркал и автопереключение (Failover):**
  * `DEFAULT_MIRRORS`: список открытых зеркал (`https://rezka-ua.pub`, `https://hdrezka.me`, `https://rezka.ag`, `https://hdrezka-home.tv`).
  * `set_base_url(url)` и `get_base_url()`: динамическое управление активным доменом.
  * При поиске (`search_movies`) лаунчер автоматически пробует зеркала по очереди. Если текущее зеркало заблокировано или не отвечает, выбирается следующее рабочее и сохраняется в `BASE_URL`.
  * **Типы зеркал:**
    * *Открытые каталоги:* `rezka-ua.pub`, `hdrezka.me`, `rezka.ag`, `hdrezka-home.tv` — работают без авторизации, поддерживают прямой поиск.
    * *Шлюзы авторизации:* `rezka.fi`, `rezka.si`, `rezkify.com` — содержат форму входа (`#loginForm`), требуют аккаунта и сессионных cookie.
    * *Официальные источники свежих зеркал:* Telegram-бот `@hdrezkaclientbot` (команда `/mirror`) и почта `mirror@hdrezka.org`.
* **Поиск:**
  * Обязательные параметры DLE: `/search/?do=search&subaction=search&q=<QUERY>`.
  * Без `do=search&subaction=search` сайт игнорирует запрос и возвращает новинки каталога!
  * Карточки фильмов извлекаются из селектора `.b-content__inline_item`.
  * Функция `rank_search_results` ранжирует результаты по релевантности названия.
* **Антибот-защита Anubis (Proof-of-Work):**
  * Прямой HTTP-запрос к странице фильма отдает страницу проверки `<title>Подождите, идёт проверка...</title>`.
  * Для обхода используется Selenium в headless-режиме (`create_headless_driver()`) со скрытием автоматизации (`--disable-blink-features=AutomationControlled`, исключение флага `enable-automation`).
  * Скрипт ожидает завершения проверки Anubis (исчезновения слова «проверка» из заголовка и появления плеера).
* **Озвучки и переводы:**
  * Элементы озвучек на странице: `.b-translator__item` (атрибут `data-translator_id`, название в `innerText`).
  * Смена озвучки выполняется через AJAX-эндпоинт:
    ```http
    POST /ajax/get_cdn_series/?t=<timestamp>
    Content-Type: application/x-www-form-urlencoded

    action=get_movie&id=<POST_ID>&translator_id=<ID>&is_camrip=0&is_ads=0&is_director=0
    ```
  * Ответ содержит JSON: `{"success": true, "url": "[360p]url or alt_url,[720p]...[1080p]..."}`.
* **Парсинг качества:**
  * Функция `parse_streams_with_qualities` разбивает строку на качества (`1080p`, `720p`, `480p`, `360p`), очищает экранированные слэши `\/` и разделяет зеркала (`ukrtelcdn` / `voidboost`).

### 3.1a. Ход загрузки и отмена (`progress.py`)
* Шаги отправляются событием `load_progress` через `Progress.step(name)`: только реальные шаги, без процента.
* `cancel` выполняется вне очереди Selenium. Циклы ожидания проверяют `progress.check()`; если операция не прервалась за 3 секунды, Chrome закрывается, и следующая загрузка запускает новый.

### 3.1b. Пресеты (`machine.py`, `settings.py`)
* `preset`: `auto`, `high`, `mid`, `low`. High — `desktop-4070ti.conf`, Mid — `mid.conf`, Low — `low.conf`. Флаги CLI остаются прежними.
* RTX VSR: на High для фильмов, Windows и GeForce RTX с драйвером не ниже 531.18 (RTX 20: 545.84) вместо шейдеров включается `d3d11vpp` с меткой `@vsr`. Драйвер не сообщает, применил ли он улучшение, поэтому меню плеера пишет «Включён, RTX VSR». На аниме VSR не проверялся.
* Авто: `machine.classify_gpus` определяет класс по названию; виртуальные адаптеры отбрасываются, неизвестная модель получает Low.

### 3.2. Апскейл и шейдеры (`presets.py`, `shaders.py`, `mpv-profiles/`)
* **Поддерживаемые GPU-профили:**
  * `desktop-4070ti` (Windows + дискретная NVIDIA GPU):
    * `vo=gpu-next`, на Windows `--gpu-api=d3d11` (с Vulkan при интерполяции были подфризы), `profile=gpu-hq`, `scale=ewa_lanczossharp`.
    * Шейдер кино (`[film]`): `FSRCNNX_x2_16-0-4-1.glsl` (16-слойная нейросеть x2 prescaler).
    * Шейдер аниме (`[anime]`): `Anime4K_Restore_CNN_VL`, `Anime4K_Upscale_CNN_x2_VL` и др.
  * `air-m1` (macOS Apple Silicon): облегченный `FSRCNNX_x2_8-0-4-1.glsl` + `KrigBilateral.glsl`.
  * `generic`: встроенный высококачественный `--profile=gpu-hq` без внешних файлов.
* **Генератор кадров (Интерполяция):**
  * Для реальной плавности используется:
    ```ini
    video-sync=display-resample
    interpolation=yes
    tscale=mitchell
    tscale-clamp=0
    blend-subtitles=yes
    ```
  * **Важно:** Не используйте `tscale=oversample`, если нужна визуальная плавность — `oversample` сохраняет жесткую дискретность 24 кадров/сек (nearest neighbor). `tscale=mitchell` создает плавный блендинг под герцовку монитора.
* **Автозагрузка шейдеров (`shaders.py`):**
  * При первом старте модуль `ensure_shaders_installed()` автоматически скачивает шейдеры FSRCNNX, KrigBilateral и архив Anime4K v4.0.1 в системную папку `%APPDATA%\mpv\shaders` и в локальную `mpv-profiles/shaders/`.

### 3.3. Приложение и плеер (`app/`, `backend.py`, `mpv-profiles/player/`)
* **Архитектура:** Svelte → команда Tauri `backend_call` → Rust (`backend.rs`) → JSON Lines через stdin/stdout → `backend.py`. Вся логика остаётся в Python. Протокол: `specs/003-app-player-ui/contracts/backend-protocol.md`.
* **stdout backend — это протокол.** При старте `backend.py` забирает настоящие потоки себе, а fd 1 перенаправляет в stderr, поэтому `print`, Chrome и mpv его не ломают. Журнал: `%LOCALAPPDATA%\dev.shura4eburek.mpvcinema\logs\backend.log`.
* **Многопоточность:** операции Selenium идут по одной в очереди `jobs.py`, постеры и запуск mpv выполняются отдельно. Интерфейс отбрасывает устаревшие ответы по номеру запроса.
* **Данные с сайта недоверенные:** в Svelte нельзя использовать `{@html}`, адреса проверяются в `backend.py`, CSP задан в `tauri.conf.json`.
* **Постеры:** кэшируются в `%LOCALAPPDATA%\mpv-cinema-launcher\posters` и показываются через протокол `asset`, ограниченный этим каталогом.
* **Плеер:** `presets.py` подключает `uosc` и `cinema.lua` аргументами запуска; глобальный конфиг mpv не меняется. `cinema.lua` определяет состояние апскейла по `vo-passes`.
* **Метки качества:** приходят с сайта и завышены на ступень: `1080p` на деле 1280×720. Реальное разрешение показывает плеер.

### 3.2a. Кеш страницы фильма (`backend.py`)

Страница и потоки озвучки хранятся в памяти 5 минут, отдельно для каждой озвучки. При попадании в кеш `_stream_times` получает время этих ссылок, поэтому устаревшие ссылки KinoGo обновятся при запуске. Сбой воспроизведения стирает кеш фильма.

### 3.2b. Lampac (`lampac_server.py`, `lampac.py`, `LampacSources.svelte`)

Lampac 1.87.6 — отдельная неизменённая программа (AGPL-3.0), с ASP.NET Runtime входит в установщик Windows. `build_windows.ps1` скачивает её с проверкой сумм и убирает браузер, файлы других систем и лишние модули; при обновлении поменять версию и суммы и заново пройти `specs/007-lampac-sources/quickstart.md`. При первом включении копия кладётся в кеш приложения: Lampac пишет рядом с собой. Сервер слушает только `127.0.0.1`, порт свободный, процессы в Job Object.

Ловушки: кеш Lampac ключуется по `id`, поэтому номер считается из названия и года; `show: true` не значит, что фильм найден, источник показывается только после `type: movie`. Браузерные модули не использовать.

При запуске из исходников Lampac берётся из `app/src-tauri/resources/lampac`, который готовит `build_windows.ps1`. Другой каталог задаётся переменной `MPV_CINEMA_LAMPAC_DIR`. Если каталога нет, настройка Lampac скрыта.

### 3.2e. Плеер на странице (`player_surface.rs`, `player_ipc.py`, `surface.ts`, `Movie.svelte`)

Экспериментальная настройка `embedded_player`, только Windows, по умолчанию выключена. Спецификация и итоги проб: `specs/009-embedded-player/`.

* **Устройство:** mpv остаётся отдельным процессом и рисует через `--wid` в дочернее окно `MpvCinemaSurface`. `Movie.svelte` на каждом кадре сообщает положение элемента `.player`, а Rust двигает окно и обрезает его по верху `main` регионом.
* **Окно всегда поверх страницы.** Интерфейс приложения поверх видео показать нельзя: прозрачность главного окна открывает рабочий стол, а не mpv. Работает только отдельное прозрачное окно верхнего уровня, в проекте его нет. Поэтому списки открываются ниже плеера, а настройки и трейлер останавливают просмотр.
* **Мышь:** mpv отключает встроенное окно (`WS_DISABLED`), поэтому область включает его через `EnableWindow`. Простая пересылка сообщений мыши не подходит: `hover` остаётся выключенным, и uosc не работает.
* **Настройки запуска:** профили задают `fs=yes`, поэтому встроенный режим добавляет `--fullscreen=no`. Также `--keep-open=yes`: плеер остаётся после конца фильма и закрывается кнопкой uosc или страницы.
* **Полный экран:** mpv сам не разворачивает окно. `player_ipc.py` читает свойство `fullscreen` через канал управления, интерфейс вызывает `player_surface_fullscreen`.
* **Завершение:** в отличие от отдельного окна, встроенный плеер закрывается вместе с приложением. Новый запуск сначала завершает прежний. Ссылка из буфера играет в отдельном окне.
* **Прокрутка:** страница прокручивается скачками по шагу колеса, видео догоняет её с задержкой до 30–60 мс. Под плеером лежит размытый постер, чтобы разрыв не был чёрным.

### 3.2d. uosc

Опции, кнопки и сообщения скриптов uosc 5.13.0 и их применение в проекте: [docs/uosc.md](docs/uosc.md). Читать перед правкой интерфейса плеера.

### 3.2c. Сериалы (`scraper.py`, `kinogo.py`, `sources.py`, метод `episode`)

* **Что считается сериалом:** наличие серий (`.b-simple_episode__item` на HDRezka, список `Серия N` в плеере KinoGo), а не адрес и не название. Страница возвращает `series`, у фильма там `null`.
* **Метод `episode`** отдаёт потоки вместе со списками: набор серий зависит от озвучки, набор озвучек от сезона. `translator_streams` остаётся только для фильмов. Кеш и обновление ссылок учитывают озвучку, сезон и серию.
* **HDRezka:** `get_episodes` возвращает сезоны и серии озвучки, `get_stream` возвращает потоки серии. Запрос `get_movie` для сериала сайт отклоняет. Сообщение «Время сессии истекло» означает любые неверные параметры, а не истёкшую сессию.
* **KinoGo:** роль списка в плеере определяет `classify_groups` по кнопкам. Порядок переключения: сезон, озвучка, снова сезон, серия. Серии известны только у текущего сезона, у остальных `episodes` пуст, и интерфейс получает их после выбора сезона.
* **Поток KinoGo:** путь сериала `/tvseries/`. Проверка минимальной длины для сериала отключена. Если узел верхнего варианта не отвечает, у сериала добавляется «Качество не подтверждено» с сервера плеера; интерфейс выбирает этот вариант по умолчанию.
* **Автооткрытие:** если KinoGo не дал видео, `sources.single_match` ищет на HDRezka одно совпадение по названию, типу и году, и страница открывается сразу (`switched_from`). При сомнении остаётся список. Ответ лежит в кеше под адресом KinoGo, а содержит адрес HDRezka, поэтому `_forget_page` проверяет оба.

### 3.3a. Трейлер и масштаб (`trailers.py`, `Trailer.svelte`, `scale.ts`)

* Трейлер ищется по странице результатов YouTube, без ключа; разметка может измениться, тогда кнопка предлагает браузер. Адрес для браузера строит backend.
* Плеер встроен с `youtube-nocookie.com`, в CSP разрешён только этот адрес. Автозапуск и `unMute` не использовать: плеер глушит такой ролик и сводит громкость к нулю, поэтому зритель сам нажимает Play. При `onError` берётся следующий ролик.
* Масштаб задаёт `zoom` на `<html>` из `scale.ts`. Значения в px в компонентах писать как для окна 1800×1000.
* В песочнице с подменённым `LOCALAPPDATA` постеры и фон не показываются: область `assetProtocol` не видит этот путь.

### 3.4. Поиск плеера mpv (`locate.py`)
* Ищет `mpv.exe` / `mpvnet.exe` в следующем порядке:
  1. Системный `PATH` (`shutil.which`).
  2. Каталог установки Winget: `C:\Program Files\MPV Player\mpv.exe` (пакет `shinchiro.mpv`).
  3. Стандартные каталоги `Program Files\mpv`, `mpv.net`.
  4. Реестр Windows (`HKLM` и `HKCU` Uninstall / App Paths).
  5. Для macOS: `/opt/homebrew/bin/mpv`, `/Applications/mpv.app`.

## 6. Памятка для будущих AI-разработчиков (FAQ и типичные ошибки)

1. **Если изменилась верстка HDRezka:**
   * Проверяйте структуру селекторов в `scraper.py`: `.b-content__inline_item` (карточки поиска) и `.b-translator__item` (список озвучек).
2. **Если видео открывается, но пишет «Шейдер не найден»:**
   * Проверьте наличие файлов в `%APPDATA%\mpv\shaders\` (`Get-ChildItem "$env:APPDATA\mpv\shaders"`). Запустите `shaders.ensure_shaders_installed()`.
3. **FSRCNNX не отображается на экране 1 в `Shift + I`:**
   * `Shift + I` показывает базовый скейлер (`ewa_lanczossharp`). Чтобы увидеть нейросеть, нажмите цифру **`2`** в mpv — откроется страница `GLSL shaders`.
   * Помните про условие шейдера `> 1.3x`: на видео 1080p на мониторе 1080p нейросеть спать будет намеренно (апскейл не нужен).
4. **Не передавайте параметры поиска без `do=search`:**
   * URL должен строго быть `.../search/?do=search&subaction=search&q=...`.
