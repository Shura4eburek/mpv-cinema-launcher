# Research — mpv HLS Launcher (Phase 0)

Решения по открытым вопросам из спецификации и по техническому стеку.

## R1. Язык и упаковка

- **Decision**: Python 3.10+, stdlib-only, оформлено как пакет `mpv_launcher` с
  console-script `mpvplay` (через `pyproject.toml`). Запуск также доступен как
  `python -m mpv_launcher`.
- **Rationale**: Python есть на обеих целевых ОС; нет шага сборки; богатая stdlib
  закрывает все потребности (argparse, subprocess, platform). Console-script даёт
  удобную команду `mpvplay "<url>"` на обеих системах.
- **Alternatives considered**: Go/Rust (статичный бинарь, но нужен кросс-билд и
  CI под две ОС — избыточно для лаунчера); shell-скрипты (не кроссплатформенно:
  bash на Windows отсутствует «из коробки»).

## R2. Чтение буфера обмена без pip-зависимостей

- **Decision**: платформенная команда через `subprocess`:
  - macOS: `pbpaste`;
  - Windows: `powershell -NoProfile -Command Get-Clipboard`;
  - Linux (best-effort): `wl-paste` → `xclip -o` → `xsel -b`, если найдены.
  Результат обрезается по пробелам; берётся первая непустая строка.
- **Rationale**: не тянем `pyperclip`/`pywin32`; команды есть в штатных системах.
- **Alternatives considered**: `pyperclip` (лишняя зависимость); `tkinter` clipboard
  (тянет GUI-тулкит, на headless/Server-сборках ненадёжно).

## R3. Автоопределение класса машины

- **Decision**: эвристика по `platform`:
  - `Darwin` + arch `arm64` → профиль **air-m1** (мобильный/облегчённый);
  - `Windows` → попытка увидеть дискретную NVIDIA (наличие `nvidia-smi` в PATH
    **или** успешный его вызов) → профиль **desktop-4070ti** (тяжёлый);
  - иначе → **generic** (безопасный облегчённый профиль без тяжёлых шейдеров).
  Флаг `--profile {auto|desktop-4070ti|air-m1|generic}` переопределяет (default `auto`).
- **Rationale**: соответствует двум реальным машинам пользователя; при неуверенности
  выбирается щадящий вариант (FR-013). `nvidia-smi` — дешёвый и надёжный признак
  рабочей dGPU NVIDIA.
- **Alternatives considered**: парсинг `wmic`/`system_profiler` для точной модели GPU
  (хрупко, медленно, избыточно — классов всего два-три); запрос у пользователя при
  каждом старте (мешает цели «одно действие»).

## R4. Пресеты контента (кино / аниме)

- **Decision**: взаимоисключающие флаги `--film` (default) и `--anime`. Пресет
  влияет только на то, какой набор шейдеров/опций апскейла подставляется.
- **Rationale**: простой, предсказуемый выбор; совпадает с FR-007/FR-008.
- **Alternatives considered**: автоопределение аниме по метаданным потока (ненадёжно,
  вне scope); рантайм-переключение внутри mpv хоткеями (возможно как дополнение
  через `input.conf`, но не основной механизм выбора).

## R5. Как профиль+пресет превращаются в аргументы mpv

- **Decision**: визуальные настройки живут в `mpv-profiles/<profile>.conf` как именованные
  mpv-профили (секции `[film]`, `[anime]`). Лаунчер передаёт mpv:
  `--include=<profile>.conf --profile=<film|anime> <url>` (+ опц. заголовки). Таблица
  «класс машины → файл конфига» и «пресет → имя mpv-профиля» задаётся в `presets.py`.
- **Rationale**: тяжёлые/хрупкие строки шейдеров не хардкодятся в Python; качество
  правится редактированием `.conf` без изменения кода; `presets.py` остаётся простым и
  тестируемым (возвращает список строк-аргументов).
- **Alternatives considered**: хардкод всех `--glsl-shaders=...` в Python (дублирование,
  тяжело поддерживать); генерация временного mpv.conf на лету (лишняя файловая возня).

## R6. Отсутствие mpv / шейдеров

- **Decision**:
  - **mpv не найден** (`shutil.which("mpv")` пуст) → ошибка на stderr с подсказкой
    по установке, код выхода ≠ 0 (FR-011).
  - **конфиг профиля отсутствует** в `mpv-profiles/` → предупреждение на stderr и
    **деградация**: запуск mpv с базовым встроенным апскейлом (`--profile=gpu-hq`,
    `scale=ewa_lanczossharp`) без внешних шейдеров (FR-012).
  - Проверять наличие самих файлов шейдеров лаунчер не обязан (их подключает mpv);
    если mpv не найдёт шейдер — он сам сообщит, лаунчер это не маскирует.
- **Rationale**: предсказуемое, заранее описанное поведение; просмотр возможен даже
  без шейдеров (пусть и проще по качеству).
- **Alternatives considered**: жёсткий отказ при отсутствии шейдеров (хуже UX); тихое
  игнорирование (нарушает «предсказуемость» из спеки).

## R7. HTTP-заголовки

- **Decision**: повторяемый флаг `--header "Name: Value"` плюс удобные
  `--referer URL` и `--user-agent STR`. Собираются в одну строку и передаются как
  `--http-header-fields="h1,h2,..."`. По умолчанию заголовки не добавляются.
- **Rationale**: закрывает FR-009; проверенные CDN работают и без заголовков, так что
  это опция на случай требовательного CDN.
- **Alternatives considered**: всегда слать фиксированный Referer (ломает CDN, которым
  он не нужен/мешает).

## R8. Валидация ссылки

- **Decision**: принимать строку, которая парсится `urllib.parse` как `http`/`https`
  с непустым host. `.m3u8` в пути — не обязателен (мастер-плейлисты встречаются и с
  иными путями), но наличие `.m3u8`/`hls` повышает уверенность и логируется. Пустой/
  не-URL ввод → понятная ошибка, код ≠ 0 (FR-003).
- **Rationale**: не ложимся на строгий суффикс (реальные ссылки видели без `.m3u8` в
  хвосте), но отсекаем явный мусор и пустой буфер.
- **Alternatives considered**: требовать строго `.m3u8` (отсечёт валидные мастер-URL);
  HEAD-запрос для проверки доступности (сеть на старте — лишняя задержка и вне scope;
  доступность проверит сам mpv).

## Resolved clarifications

Все три «умолчания» из спецификации закрыты: R3 (детекция машины + override),
R4 (пресет флагом, default film), R6 (деградация при отсутствии шейдеров). Открытых
`NEEDS CLARIFICATION` не осталось.
