# Feature Specification: Синхронизация «Моего списка» через Google Drive

**Feature Branch**: `013-drive-sync`

**Created**: 2026-11-16

**Status**: Draft

**Input**: User description: "Синхронизация «Моего списка» через Google Drive (issue #11, этап 3). Вошедший через Google пользователь видит один и тот же список (записи и статусы Смотрю/Просмотрено/Запланировано) на всех своих устройствах. Список хранится файлом watchlist.json в скрытой папке приложения в Google Drive (appDataFolder), пользователю в Drive не виден. Pull при старте и сразу после входа; push с задержкой после локальных изменений. Слияние по записи: last-write-wins по updated_at; удаления — tombstones. Офлайн: изменения копятся локально и уходят при следующей синхронизации. Индикатор состояния синхронизации и понятные ошибки; истёкший доступ — предложение войти заново. Без входа список только локальный. Первый вход с непустым локальным списком — объединение без потерь. Выход не удаляет локальный список. Вне рамок: совместные списки, история версий, синхронизация настроек."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Один список на всех устройствах (Priority: P1)

Пользователь вошёл через Google на двух компьютерах. На первом он добавляет фильм в «Мой список» со статусом «Запланировано». Через короткое время на втором компьютере (при запуске или пока приложение открыто) этот фильм появляется в списке с тем же статусом. Изменение статуса, отметки серий и удаление переносятся так же.

**Why this priority**: Это и есть цель этапа: список не привязан к одному компьютеру.

**Independent Test**: Войти одним аккаунтом на двух устройствах, изменить список на первом, перезапустить второе — изменения на месте.

**Acceptance Scenarios**:

1. **Given** пользователь вошёл, **When** он меняет список (добавляет, меняет статус, отмечает серию, удаляет), **Then** изменение сохраняется в облаке не позже чем через 10 секунд после последнего изменения подряд.
2. **Given** на другом устройстве список изменился, **When** приложение запускается или пользователь только что вошёл, **Then** список подтягивается из облака и показывает изменения.
3. **Given** одна и та же запись изменена на двух устройствах, **When** списки объединяются, **Then** остаётся вариант с более поздним временем изменения.
4. **Given** запись удалена на одном устройстве, **When** другое устройство синхронизируется, **Then** запись удаляется и на нём и не возвращается при следующих синхронизациях.
5. **Given** запись удалена на одном устройстве, а позже снова добавлена на другом, **When** списки объединяются, **Then** запись есть (более позднее действие побеждает).

### User Story 2 - Видно, что происходит с синхронизацией (Priority: P2)

Пользователь видит в приложении, синхронизирован ли его список: «Синхронизировано», «Синхронизация…», «Нет связи — изменения отправятся позже» или ошибку с понятным текстом. Если доступ к Google истёк или отозван, ему предлагают войти заново.

**Why this priority**: Без индикатора пользователь не знает, можно ли доверять списку на другом устройстве.

**Independent Test**: Отключить сеть, изменить список — индикатор показывает «нет связи»; включить сеть — индикатор переходит в «Синхронизировано».

**Acceptance Scenarios**:

1. **Given** пользователь вошёл и синхронизация прошла, **When** он смотрит на индикатор, **Then** видит «Синхронизировано» и время последней синхронизации.
2. **Given** идёт синхронизация, **When** он смотрит на индикатор, **Then** видит «Синхронизация…».
3. **Given** нет сети, **When** список изменён, **Then** индикатор показывает «Нет связи», изменения не теряются.
4. **Given** доступ отозван или истёк, **When** синхронизация не удалась из-за этого, **Then** индикатор показывает «Нужно войти заново» и ведёт к входу.
5. **Given** пользователь не вошёл, **When** он смотрит на список, **Then** индикатора синхронизации нет (или «Только на этом устройстве»), список работает как раньше.

### User Story 3 - Работа без сети и первый вход (Priority: P3)

Пользователь меняет список без интернета — изменения отправляются сами, когда связь появляется. Пользователь, у которого уже есть локальный список, входит впервые (или на новом устройстве) — его локальный список объединяется с облачным, ничего не пропадает. После выхода из аккаунта локальный список остаётся на месте.

**Why this priority**: Защищает от потери данных в редких, но болезненных случаях.

**Independent Test**: На устройстве с непустым списком войти в аккаунт, у которого в облаке другой список, — в результате на обоих устройствах объединённый список.

**Acceptance Scenarios**:

1. **Given** изменения сделаны без сети, **When** связь появилась (следующая попытка синхронизации или перезапуск), **Then** изменения уходят в облако без действий пользователя.
2. **Given** локальный список непустой и в облаке есть другой список, **When** пользователь входит, **Then** получается объединение обоих; записи, которые есть в обоих, решаются по времени изменения.
3. **Given** в облаке ещё нет списка, **When** пользователь входит, **Then** облачный список создаётся из локального.
4. **Given** пользователь вошёл, **When** он выходит из аккаунта, **Then** локальный список остаётся, синхронизация прекращается, облачный список не трогается.
5. **Given** пользователь выходит и входит другим аккаунтом, **When** синхронизация идёт, **Then** локальный список объединяется с облачным списком нового аккаунта.

---

### Edge Cases

- Облачный файл повреждён или имеет неизвестный формат: локальный список не перезаписывается, показывается ошибка синхронизации, облачный файл не удаляется молча.
- Облачный файл записан более новой версией приложения: неизвестные поля записей не теряются при слиянии.
- Два устройства отправляют изменения почти одновременно: ни одно изменение не теряется молча (повторное объединение перед записью).
- Часы на устройствах расходятся: побеждает запись с более поздним временем; расхождение часов принимается как допустимый риск.
- Пользователь закрывает приложение в течение задержки перед отправкой: отправка выполняется при закрытии или при следующем запуске.
- Много записей (сотни): синхронизация не тормозит интерфейс.
- Удалённые записи копятся: старые отметки удаления (старше 90 дней) можно убирать.
- Вход выполнен, но облачная папка приложения недоступна (квота, ограничения Google): понятная ошибка, локальный список работает.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Для вошедшего пользователя приложение MUST хранить копию «Моего списка» в скрытой папке приложения в его Google Drive; файл не виден в обычном интерфейсе Drive.
- **FR-002**: Приложение MUST подтягивать облачный список при запуске (если пользователь вошёл) и сразу после успешного входа.
- **FR-003**: После локального изменения списка приложение MUST отправлять его в облако с задержкой, объединяя серию изменений подряд в одну отправку; не позже 10 секунд после последнего изменения при наличии сети.
- **FR-004**: Объединение MUST выполняться по каждой записи отдельно: побеждает вариант с более поздним временем изменения; записи, которые есть только в одном списке, сохраняются.
- **FR-005**: Удаления MUST переноситься между устройствами: удалённая запись не возвращается с устройства, где она осталась более старой.
- **FR-006**: Изменения, сделанные без сети или при ошибке, MUST сохраняться локально и отправляться при следующей успешной синхронизации без действий пользователя.
- **FR-007**: Приложение MUST показывать состояние синхронизации: «Синхронизировано» (с временем), «Синхронизация…», «Нет связи», «Нужно войти заново», «Ошибка синхронизации» с понятным текстом на русском.
- **FR-008**: При истёкшем или отозванном доступе приложение MUST прекращать попытки синхронизации и предлагать войти заново; после входа синхронизация возобновляется и ничего не теряется.
- **FR-009**: Без входа «Мой список» MUST работать только локально, как до этого этапа; никаких сетевых запросов к Drive.
- **FR-010**: Выход из аккаунта MUST оставлять локальный список нетронутым и не изменять облачный.
- **FR-011**: Приложение MUST позволять запустить синхронизацию вручную (например, кнопкой у индикатора).
- **FR-012**: Если облачный файл нельзя прочитать, приложение MUST не перезаписывать ни локальный, ни облачный список и показывать ошибку.
- **FR-013**: Синхронизация MUST выполняться в фоне и не блокировать поиск, просмотр и работу со списком.

### Key Entities

- **Запись списка**: фильм или сериал со статусом, отметками серий и временем последнего изменения; удалённая запись хранится как отметка удаления со временем.
- **Облачный список**: копия всех записей списка (включая отметки удаления) в скрытой папке приложения в Google Drive пользователя.
- **Состояние синхронизации**: текущее состояние (синхронизировано / идёт / нет связи / нужен вход / ошибка), время последней успешной синхронизации, признак неотправленных изменений.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Изменение на одном устройстве появляется на другом после его перезапуска в 100% случаев при наличии сети.
- **SC-002**: Изменение уходит в облако не позже 10 секунд после последнего изменения подряд при наличии сети.
- **SC-003**: В сценариях офлайн-изменений, первого входа с непустым списком и одновременных изменений на двух устройствах не теряется ни одна запись (проверка сравнением списков).
- **SC-004**: Удалённая запись не возвращается ни на одном устройстве после трёх циклов синхронизации.
- **SC-005**: Синхронизация списка из 500 записей не вызывает заметных задержек интерфейса (действия со списком отвечают так же, как без входа).
- **SC-006**: Без входа все сценарии «Моего списка» проходят без изменений и без сетевых обращений к Drive.

## Assumptions

- Вход через Google и право на скрытую папку приложения уже есть (этап 1, #14).
- Записи списка уже хранят время последнего изменения, а удаления — как отметки удаления (этап 2, #12).
- Синхронизация в фоне, пока приложение открыто, кроме запуска и входа: периодическая проверка облака раз в несколько минут допустима, но не обязательна — достаточно запуска, входа и ручной кнопки.
- Отметки удаления старше 90 дней можно удалять из списков.
- Один облачный список на аккаунт; совместные списки, история версий и синхронизация настроек вне рамок.
- Расхождение системных часов между устройствами не компенсируется.
