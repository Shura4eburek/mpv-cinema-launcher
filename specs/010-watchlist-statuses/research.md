# Research: Мой список со статусами просмотра

## R1. Откуда брать id IMDb и КиноПоиска

**Проверено** 2026-11-16 на `uakinogo.io/filmy/109870-bitva-motorov.html`: на странице есть только рейтинги «IMDB» и «КиноПоиск» в блоке фактов (их и сейчас разбирает `kinogo.py`). Ссылок на imdb.com или kinopoisk.ru и id в разметке нет. Плеер `cinemar.cc/embed/118774/…` использует собственный номер, а не id КиноПоиска. Lampac получает от приложения название и год, а номер `stable_id` вычисляет само приложение, так что id из него не взять.

**Decision**: id IMDb ищется через открытый сервис подсказок `https://v3.sg.media-imdb.com/suggestion/x/<запрос>.json` по оригинальному названию (или русскому, если оригинального нет). Совпадение принимается, только если одновременно:
- нормализованное название совпадает с полем `l`;
- год `y` совпадает с годом страницы (±1 для сериалов: год начала показа на сайтах часто расходится);
- тип совпадает: `qid` из `movie`/`tvMovie` → фильм, `tvSeries`/`tvMiniSeries` → сериал;
- подходящий кандидат ровно один.

В остальных случаях id не ставится и работает запасной ключ. Результат поиска, включая «не найдено», запоминается в файле списка на 7 дней, чтобы не повторять запросы.

**Rationale**: без ключа API и регистрации; проверка вручную (`the matrix` → `tt0133093`, 1999, `movie`) прошла; ответ маленький (~10 кандидатов).

**Alternatives considered**: TMDB и неофициальный API КиноПоиска требуют ключ; поиск через Lampac есть не у всех (Lampac выключен по умолчанию); разбор страницы imdb.com тяжёлый и хрупкий.

**Риск**: неофициальный сервис может измениться. Сбой не ломает список: остаётся запасной ключ.

**Уточнение при реализации**: сбой сети (`imdb.Unavailable`) не записывается как «не найдено», иначе id не искался бы неделю; поиск повторится при следующем открытии страницы. Проверено вживую: The Matrix 1999 → `tt0133093`, The Lazarus Project 2022 (сериал) → `tt14190592`, Dune 2021 → `tt1160419`; русское название не находит ничего, поэтому запрос идёт по оригинальному.

## R2. id КиноПоиска

**Decision**: формат ключа `kp:<число>` поддерживается в модели и переносе записей, но в этой фиче id КиноПоиска ниоткуда не приходит. Он понадобится, когда появится источник с ним.

**Rationale**: решение владельца проекта: «ID imdb или кинопоиска». Сейчас доступен только путь через IMDb.

## R3. Запасной ключ

**Decision**: `t:<тип>:<год>:<нормализованное название>`. Нормализация: оригинальное название (если нет — русское без «(N сезон)» и части после « / »), нижний регистр, ё→е, только буквы и цифры через один пробел.

**Rationale**: тот же тайтл через kinogo и Lampac открывается с одной страницы kinogo, у него одинаковые название и год, значит и ключ один.

## R4. Конец просмотра

**Проверено** в коде: канал управления mpv (`--input-ipc-server`) подключается только для встроенного плеера (`ipc_server` при `wid`), наблюдаются `fullscreen` и `time-pos`.

**Decision**: канал подключается для обоих режимов: на Windows — именованный канал, на macOS — Unix-сокет в `/tmp` (T034), дополнительно наблюдаются `duration` и `eof-reached`. Встроенный плеер работает с `--keep-open` и после конца не закрывается, а его закрытие считается отменой: поэтому конец файла засчитывается сразу, а позиция ≥ 95% — и при обычном завершении, и при закрытии встроенного плеера. «Досмотрено» — когда последняя полученная позиция ≥ 95% длительности или пришло `eof-reached: true`. Решение принимает `backend.py` после завершения mpv.

**Alternatives considered**: `--save-position-on-quit` и разбор `watch_later` не подходит, если досмотрено до конца (файл удаляется); скрипт Lua в `cinema.lua` дублировал бы уже работающий канал.

## R5. Где принимается решение о статусе после просмотра

**Decision**: в `play` приходит параметр `watch` (ключ, данные записи, сезон, серия, признак «последняя серия»). При запуске `backend.py` ставит «Смотрю» (если не «Просмотрено»). При досмотре отмечает серию и отправляет событие `watch_completed`. Предложение «Просмотрено?» показывает `App.svelte`, а не `Movie.svelte`, чтобы оно появилось и после ухода со страницы.

**Rationale**: логика остаётся в Python, работает одинаково для встроенного плеера и mpv в отдельном окне и тестируется pytest.

## R6. Хранение

**Decision**: один файл `watchlist.json` в `settings.data_dir()`, запись целиком через временный файл и `os.replace` (как `settings.update`). Один замок на запись внутри процесса. Нечитаемый файл переименовывается в `watchlist.broken-<время>.json`, список начинается пустым, интерфейс получает `warning: "watchlist_reset"`.

**Rationale**: 500 записей — около 200 КБ, полная перезапись быстрая; формат один и для будущей синхронизации через Drive.

## R7. Открытие тайтла из списка

**Decision**: в записи хранится адрес страницы kinogo. При открытии адрес переводится на текущее зеркало из настроек (заменяется хост), как уже делается для адресов kinogo.
