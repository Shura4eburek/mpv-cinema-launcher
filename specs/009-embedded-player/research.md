# Research: Плеер внутри окна приложения

Собрано 2026-11-03. Разделы 1–5 записаны до опытов, это гипотезы. Итог пробы в разделе 6.

## 1. Как встроить плеер

**Decision**: отдельный процесс mpv с `--wid` и дочерним окном Win32, созданным в Rust.

**Rationale**: сохраняются шейдеры, профили, uosc и `cinema.lua`, а также нынешняя модель запуска, отмены и запасных адресов в `runner.py`. Сбой mpv не роняет приложение.

**Alternatives**:
- `tauri-plugin-libmpv`: mpv как библиотека в процессе приложения. Требует `libmpv-2.dll` и переписывания запуска; сбой плеера роняет окно. Полезен как свидетельство, что подход с прозрачностью применяется на практике.
- HTML5 и hls.js: теряются шейдеры и интерполяция, Referer и CORS требуют прокси. Отвергнуто в спецификации.

## 2. Способы наложения

Прежнее предположение «поверх видео нельзя» подтверждено не полностью, поэтому проверяются все три способа.

| Способ | Как устроен | Что известно | Что может помешать |
|--------|-------------|--------------|--------------------|
| А. Прозрачный главный веб-вид | `transparent: true` и прозрачный CSS, дочернее окно mpv под веб-видом | `tauri-plugin-libmpv` требует именно такую настройку для встраивания. Рисуется ли интерфейс поверх видео, в документации прямо не сказано | Настройка задаётся при создании окна и влияет на обычный режим; мышь уходит в веб-вид |
| Б. Отдельное прозрачное окно поверх | Владеемое окно верхнего уровня с веб-видом над областью mpv | Microsoft описывает прозрачность смешанной отрисовки как работающую только для окон верхнего уровня | Нужно вручную следовать за движением и размером окна, возможно отставание; отдельная сессия веб-вида |
| В. Без наложения | Непрозрачный веб-вид, mpv в своей области | Базовый вариант, ограничение области окна для него ожидаемо | Интерфейс только рядом с видео |

Способ на композиции (`WebView2CompositionController`) не проверяется: Tauri его не предоставляет, а старое обсуждение WinUI сообщает о проблемах с прозрачностью над чужой отрисовкой. Вернуться к нему можно, если А и Б не сработают.

**Мышь**: панель поверх видео перехватывает нажатия, а uosc управляется мышью. В А и Б проверяется пропуск нажатий вне панели, например переключением `set_ignore_cursor_events` по положению курсора.

**Тестовое видео**: `av://lavfi:testsrc2` без сети, чтобы результат не зависел от сайтов. Снимки экрана снимаются с экрана, а не из окна: снимок окна может не содержать видео mpv.

## 3. Полный экран

**Decision**: читать свойство `fullscreen` mpv через канал управления `--input-ipc-server`, разворачивать окно Tauri и растягивать дочернее окно.

**Rationale**: со встроенным окном mpv не разворачивает его сам. Канал также даёт замеры качества и закрытие плеера. Разметка uosc и клавиша `f` не меняются.

**Alternatives**: команда из `cinema.lua` в файл, как `ready_file`: нужен опрос файла. Запасной вариант, если канал не подойдёт.

## 4. Запуск и завершение

- **Экран запуска**: сигнал первого кадра остаётся прежним (`cinema-ready_file`, событие `playback-restart`). Область показывается после него, чтобы не было чёрного окна.
- **Запасные адреса**: `run_with_fallback` запускает новый процесс с тем же `--wid`.
- **Закрытие**: сейчас `Backend.close` намеренно оставляет mpv работать. Встроенный процесс завершается явно, а проверка на родительское окно служит только страховкой.
- **Второй запуск**: перед новым запуском встроенный процесс завершается (FR-013).

## 5. Замеры качества

**Decision**: через канал управления читать `vo-passes`, `frame-drop-count`, `vo-delayed-frame-count` и `estimated-vf-fps` одного и того же фильма в обоих режимах по 5 минут.

**Rationale**: сравнение с отдельным окном прямо отвечает на SC-002 и не зависит от восприятия.

## 6. Итог пробы наложения

**Исходное состояние**: pytest 492, Vitest 57, `npm run check` без ошибок.

**Как проверено**: настоящее окно Tauri в сборке разработки, mpv 0.41 с профилем приложения, uosc и `cinema.lua`, тестовое видео 1080p 24 кадра. Масштаб экрана 100%. Курсор и клавиши подавались настоящим вводом Windows, ответы mpv читались через канал управления, снимки сняты с экрана.

| Проверка | А. Прозрачное главное окно | А с обрезкой страницы | Б. Отдельное окно поверх | В. Без наложения |
|----------|----------------------------|-----------------------|--------------------------|------------------|
| Видео внутри окна | нет, сквозь окно виден рабочий стол | да, вне панели | да | да |
| Панель видна | да | да | да | нет |
| Сквозь панель видно видео | нет, виден рабочий стол | нет, виден рабочий стол | **да, с движением** | нет панели |
| Кнопка панели нажимается | да | да | да | нет панели |
| Мышь вне панели доходит до mpv | нет | да | да | да |
| Щелчок по панели не доходит до mpv | да | да | да | нет панели |
| Клавиши после работы с панелью | да | нет | да, с возвратом фокуса | да |
| Подстройка размера, мс | 78 | 94 | 62–94 | 47–62 |

**Вывод**: интерфейс поверх видео возможен, но только отдельным окном верхнего уровня (способ Б). Прозрачность главного окна открывает рабочий стол, а не дочернее окно mpv, поэтому способ А отвергнут. Прежнее предположение «поверх видео нельзя» верно только для веб-вида внутри того же окна.

**Рекомендация**: продолжать на способе В: управление остаётся в uosc, это проще и уже работает. Способ Б подключать только для конкретных элементов приложения поверх видео, если они понадобятся.

**Что выяснилось про встраивание**:

- mpv со встроенным окном ставит ему `WS_DISABLED`, и мышь уходит родителю. Без исправления uosc не работает. Рабочее решение: область включает окно mpv при первом движении мыши (`EnableWindow`) и передаёт ему фокус; после этого работают `hover`, клавиши и uosc. Простая пересылка сообщений мыши оставляла `hover` выключенным.
- uosc внутри окна работает: панель появляется, щелчок по шкале перематывает (снимок `spike/uosc-embedded.png`).
- В способе Б панель забирает клавиатуру нажатием, поэтому при уходе курсора фокус возвращается в плеер. `focusable(false)` этого не решил.
- За 60 с воспроизведения пропусков кадров 0 и в режиме В, и в режиме Б.

**Не проверено или проверено слабо**:

- Отставание панели при перетаскивании: замер по шагам `SetWindowPos` показал 0, но это не настоящее перетаскивание мышью. Оценивает владелец проекта на экране.
- Полный экран: проверено только развёрнутое окно. uosc показывает кнопку полного экрана активной, причину нужно выяснить в T018.
- Сравнение качества с отдельным окном (SC-002): не выполнялось, это T016. Окно было меньше кадра, поэтому FSRCNNX здесь не должен был включаться; проверены только `gpu-next` и масштабирование.
- `display-fps` сообщает 32 Гц. Причину не выяснял; это нужно сверить с настоящей частотой экрана до замеров SC-002.
- Масштаб экрана не 100% и второй монитор: это T021.

## 7. Решение владельца проекта (T009)

Элементы панели и управления нажимаются как в прежнем плеере. Цель режима: плеер прямо на странице фильма или сериала, как на стриминговых сервисах. Поэтому берётся способ В: страница устроена без перекрытия видео, а способ Б остаётся в запасе.

## 8. Итог пробы области на странице (T030, T031)

**Как проверено**: окно Tauri, mpv с профилем и uosc, тестовое видео, страница с шапкой, областью плеера 1000×562 и текстом. Прокрутка настоящим колесом мыши, по 100 точек за щелчок, снимки экрана примерно каждые 30–60 мс. Масштаб экрана 100%. Страница двигает область из цикла `requestAnimationFrame` командой `player_surface_move`.

| Проверка | Результат |
|----------|-----------|
| Положение в покое | Точно совпадает с элементом страницы, вплоть до рамки в 4 точки |
| Отставание при прокрутке | Страница прокручивается скачком на 100 точек, видео догоняет её за один снимок. Разрыв в одном снимке, то есть не больше 30–60 мс |
| Уход под шапку | Шапка цела на всех снимках, видео обрезается по ней |
| Возврат из-за верхнего края | Видео появляется сразу, задержка та же |
| После прокрутки вниз и обратно | Видео на прежнем месте, по снимку совпадает с рамкой |

**Что видно глазу**: в момент щелчка колеса на 1–2 кадра показывается фон элемента. На первом замере фон был зелёным для наглядности; на настоящей странице он чёрный. Прокрутка в WebView2 здесь скачками, поэтому разрыв равен шагу колеса.

**Точность**: снимки не привязаны к кадрам экрана, поэтому 30–60 мс это верхняя оценка шага замера, а не точная задержка. Масштаб не 100% и масштаб интерфейса `scale.ts` не проверялись: это T021 и T015. Настоящая страница прокручивается внутри своего элемента, а не всего окна.

**Рекомендация**: область едет со страницей, закрепление не требуется, если владелец проекта не заметит мешающего отставания.

## 9. Решение по прокрутке и проверка настоящего приложения

**Решение владельца проекта (T032)**: отставание есть, но терпимо; плеер едет со страницей. Под видео лежит размытый постер, чтобы разрыв при прокрутке не был чёрным.

**Как проверено**: настоящее окно Tauri из `npx tauri dev`, управление страницей по протоколу отладки WebView2, настоящий backend, KinoGo, mpv с профилем High и RTX VSR, настоящая мышь и клавиши. Настройки пользователя восстановлены после проверки.

| Сценарий | Результат |
|----------|-----------|
| Запуск на странице | 3,3–3,8 с до кадра; видео точно на месте элемента |
| Мышь, пробел без щелчка, перемотка по шкале uosc | работают |
| Прокрутка, масштаб интерфейса 1,4 | видео на месте |
| Размер окна | совпадение за 157 мс, цель 200 мс |
| Клавиша `f` и выход | весь экран 1920×1080, затем прежнее место |
| Другая серия, озвучка фильма | на том же месте, один плеер |
| Конец фильма | плеер остаётся, можно перемотать назад; закрытие возвращает постер |
| 10 запусков и закрытий подряд | без сбоев, 3,3–3,5 с каждый |
| Настройки, трейлер, уход со страницы | просмотр останавливается |
| Закрытие приложения во время просмотра | процессов нет через 0,2 с, одна попытка |

| Запасной адрес (первый отвечает 404) | второй играет в той же области |
| Сворачивание и разворот | плеер на месте |
| Закрытие приложения, SC-004 | 10 из 10, процессов нет через 0,2–0,3 с |

**Качество, SC-002**: один файл 480p, область и окно 1426×802, профиль High.

| Режим | Шейдеры | Пропуски | Задержанные кадры | Показано кадров |
|-------|---------|----------|-------------------|-----------------|
| На странице, 5 минут | FSRCNNX, те же проходы | 0 | 0 | 1636 |
| Отдельное окно, 5 минут | FSRCNNX, те же проходы | 0 | 0 | 1636 |
| На странице с RTX VSR, 1 минута | `d3d11vpp` | 0 | 0 | 1632 |
| Отдельное окно с RTX VSR, 1 минута | `d3d11vpp` | 0 | 0 | 1632 |

Счётчики файла с циклом 120 с дают одинаковое значение в обоих режимах, поэтому сравнивать надо режимы между собой, а не с длительностью замера. Замеры выполнены на виртуальном дисплее сеанса 1920×1080 с частотой 32 Гц, а не на мониторе пользователя 2560×1440 179 Гц. Поэтому числа подтверждают равенство режимов, но не поведение на 179 Гц.

**Не проверено**: масштаб Windows 150%, второй монитор, монитор 179 Гц, переключатель в настройках и отдельное окно при выключенной настройке вживую (есть тесты плана запуска), интерфейс при сотнях серий на странице с плеером.
