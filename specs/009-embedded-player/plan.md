# Implementation Plan: Плеер внутри окна приложения (проба на Windows)

**Branch**: `009-embedded-player` | **Date**: 2026-11-03 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/009-embedded-player/spec.md`

## Summary

mpv остаётся отдельным процессом и получает через `--wid` дочернее окно, которое занимает область плеера на странице фильма, как на стриминговых сервисах. Проба наложения завершена: интерфейс поверх видео возможен только отдельным окном, поэтому страница устроена так, чтобы её элементы не перекрывали видео (способ В). Следующий вопрос: насколько заметно видео отстаёт при прокрутке страницы. Он проверяется до остальной работы. Режим закрыт настройкой, выключенной по умолчанию.

## Technical Context

**Language/Version**: Python 3.11+, Rust 1.77+ (локально 1.97), TypeScript 5.9, Svelte 5

**Primary Dependencies**: Tauri 2, WebView2, mpv; новая зависимость Rust только `windows-sys` для дочернего окна

**Storage**: настройка `embedded_player` в `settings.json`, по умолчанию `false`

**Testing**: pytest, Vitest, `npm run check`, `cargo test`; снимки экрана и замеры mpv по [quickstart.md](quickstart.md); плавность оценивает владелец проекта

**Target Platform**: Windows 11 x64. На macOS настройки нет, поведение прежнее.

**Project Type**: настольное приложение

**Performance Goals**: пропущенных кадров не больше, чем в отдельном окне, плюс 1%; видео следует за размером окна менее чем за 0,2 с

**Constraints**: режим отдельного окна не меняется; логика предметной области остаётся в Python, Rust только управляет окнами; прозрачность главного окна не включается постоянно, пока проба не докажет, что она безопасна

**Scale/Scope**: новый модуль Rust, правки `backend.py`, `presets.py`, `cinema.lua`, `App.svelte`, `Settings.svelte`; пробная панель удаляется после итога

## Этапы

1. **Проба наложения (US1)**: тестовое видео, способы А, Б и В из [research.md](research.md), снимки экрана. Точка решения: итог показывается владельцу проекта до продолжения.
2. **Проба области на странице**: следование за элементом страницы, прокрутка, обрезка по шапке. Точка решения: владелец проекта оценивает отставание при прокрутке.
3. **Настоящий просмотр (US2, US5)**: настройка, запуск фильма на странице, сверка качества с отдельным окном.
4. **Управление (US3)**: клавиши и мышь, размер, полный экран с возвратом на место.
5. **Завершение (US4)**: смена серии на месте, закрытие плеера, уход со страницы, закрытие приложения без процессов.
6. **Итог**: выводы и рекомендация; удаление пробной панели.

## Риски

- Положение видео задаёт окно Windows, а страница живёт в WebView2: при прокрутке видео может отставать от страницы на кадр или больше. Если отставание мешает, запасной вариант: область фиксируется вверху страницы, а прокручивается только содержимое под ней.
- Окно Windows всегда выше страницы, поэтому меню, сообщения и трейлер не должны с ним пересекаться (FR-015).
- Прозрачное главное окно может сломать обычный режим или цепочку вывода mpv. Поэтому в пробе оно включается только отдельной сборкой или флагом.
- Панель поверх видео перехватывает мышь, а uosc управляется мышью. Способ считается рабочим только с пропуском нажатий вне панели.
- mpv со встроенным окном не разворачивает его сам: полный экран должно делать приложение.
- Сейчас открытый mpv намеренно переживает закрытие приложения. Встроенный плеер должен закрываться, и эту ветку нужно разделить.
