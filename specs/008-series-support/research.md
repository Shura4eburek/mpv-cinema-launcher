# Research: Поддержка сериалов

Проверено на живых сайтах 2026-11-03: «Во все тяжкие», «Мини-эпизоды», контроль — «El Camino».

## 1. Плеер KinoGo: сезоны, серии, озвучки

**Наблюдение**: у сериала три `#player .playlist-group`: «Сезон N», «Серия N», озвучки. У фильма одна группа с озвучками. У «Мини-эпизодов» в группах сезона и озвучки по одной кнопке, поэтому нынешний `_READ_VOICES` (нужно минимум 2 кнопки) принял бы за озвучки серии.

**Decision**: читать все группы со списком кнопок и текущим значением, а роль определять по тексту: есть кнопка `Сезон N` — сезоны, есть кнопка `Серия N` — серии, первая из остальных — озвучки. Достаточно одной такой кнопки: у серий бывают особые названия, на HDRezka 17-я серия 5-го сезона называется «Special». Сериал — это наличие группы серий.

**Rationale**: не зависит от порядка групп и работает при одной кнопке. Группа серий одновременно заменяет проверку адреса и названия.

**Alternatives**: брать группы по номеру — сломается при отсутствии группы сезонов; определять сериал по `/tvseries/` — путь говорит о типе, но не даёт списков.

## 2. Переключение на KinoGo

**Наблюдение**: клик по кнопке даёт новый мастер-плейлист за 0,4 с. Смена сезона сбрасывает серию на первую. Набор серий зависит от сезона (7, 13, 16). Набор озвучек зависит от сезона: «Кравец» есть только в 5-м. Смена озвучки оставила сезон 2.

**Decision**: порядок кликов «сезон → озвучка → снова сезон → серия»; уже активная кнопка не нажимается. После кликов состояние читается заново и возвращается в ответе.

**Rationale**: озвучка «Кравец» есть только в 5-м сезоне, поэтому сезон нужен до озвучки. Набор сезонов может зависеть от озвучки, поэтому сезон проверяется и после неё. Смена сезона сбрасывает серию, поэтому серия идёт последней. Изначальный порядок «озвучка → сезон» на живом сайте не смог бы включить «Кравец».

**Alternatives**: отдельная постоянная вкладка плеера — быстрее, но реклама звучит и держит браузер; нынешняя модель «открыл, взял поток, закрыл» проще и уже проверена.

## 3. Путь потока и `atlas`

**Наблюдение**: подписанный путь `/<подпись>/tvseries/<hash>/...`. `_on_host` ищет `/movies/` и падает с `ValueError`, это и есть причина ухода на HDRezka. `atlas` направляет файл на его постоянный узел, а часть узлов не отвечает: у S2E1 варианты 720p и 1080p давали `ConnectTimeout` даже при 20 с и трёх попытках, сервер плеера при этом работал. У других серий такой же сбой затрагивает другие варианты. Набор недоступных узлов со временем меняется.

**Decision**: убирать первый сегмент пути, если это подпись (`\d+-...`), вместо поиска `/movies/`. Если `atlas` не ответил совсем, работает уже готовая ветка: сервер плеера с подписью «Качество не подтверждено». Если у сериала недоступен только верхний вариант, этот вариант добавляется к остальным и выбирается по умолчанию, иначе зритель получил бы максимум 480p. У фильмов поведение прежнее.

**Rationale**: не перечисляем типы путей; для фильмов результат тот же.

## 4. Порог длительности

**Наблюдение**: серия «Мини-эпизодов» длится 173 с, порог 1200 с её отбрасывает.

**Decision**: `build_streams` получает `is_series`; для сериала (есть группа серий) порога нет, для фильма прежние 1200 с.

**Rationale**: трейлер приходит без группы серий, защита фильмов остаётся.

## 5. HDRezka

**Наблюдение**: `POST /ajax/get_cdn_series/`:
- `action=get_episodes&id&translator_id` возвращает HTML `seasons` и `episodes`.
- `action=get_stream&id&translator_id&season&episode` возвращает `url` с качествами, 0,1 с.
- На неверные параметры сайт отвечает `success:false` и сообщением «Время сессии истекло». Это отказ, а не истёкшая сессия: то же приходит на `get_movie` для сериала и на несуществующую серию.
- Набор серий зависит от озвучки: у TVShows 63, у остальных 62.
- `initCDNSeriesEvents(id, translator, season, episode, ...)` на сериале и `initCDNMoviesEvents` на фильме. У фильма элементов сезонов и серий нет.

**Decision**: сериал определяется по `.b-simple_episode__item` на странице. Текущая серия — по классу `active`. Озвучка по умолчанию при отсутствии списка озвучек — из `initCDNSeriesEvents`. Сезоны собираются из `data-season_id` серий, названия берутся из `.b-simple_season__item`, при их отсутствии «Сезон N». `success:false` на `get_stream` означает `no_streams`.

**Rationale**: один разбор и для страницы, и для ответа `get_episodes`, разметка там одна.

## 6. Метод протокола

**Decision**: новый метод `episode`, `translator_streams` остаётся для фильмов без изменений.

**Rationale**: ответу нужны списки, а не только потоки, и менять ответ старого метода значило бы переписывать ветку фильмов.

**Alternatives**: расширить `translator_streams` — форма ответа зависела бы от типа страницы.

## 7. Автооткрытие HDRezka

**Наблюдение**: `clean_title` убирает только год, поэтому HDRezka ищется по строке «Во все тяжкие (1-5 сезон)». Выдача содержит и «Мини-эпизоды», и «Медведи», поэтому брать первый результат нельзя.

**Decision**:
- `clean_title` убирает и `(1-5 сезон)`.
- Совпадение — равенство нормализованного названия или одной из частей через ` / `.
- Тип учитывается: у HDRezka сериал — это `/series/` или диапазон лет в `info`; у KinoGo — `/serialy/` или отметка сезона в названии. Если тип KinoGo неизвестен (страница не загрузилась и нет адреса), тип не сравнивается.
- Год отсекает тёзок и при одном совпадении, с запасом в год: сайты расходятся в дате выхода. Несколько совпадений уточняются точным годом; если их всё ещё не одно, показывается список.
- Если страница HDRezka загрузилась пустой, показывается список.

**Rationale**: автооткрытие без подтверждения допустимо только для однозначного совпадения.

**Важно**: ответ `movie` кешируется по адресу KinoGo, а содержит адрес HDRezka. Поэтому `_forget_page` должен сравнивать и адрес внутри ответа, иначе после сбоя воспроизведения вернутся старые ссылки.

## 8. Рекомендации

**Наблюдение**: `kinogo._related` и `scraper.parse_related` отбрасывают сериалы только потому, что запуск не проверялся.

**Decision**: убрать фильтры и изменить проверяющие их тесты.

## 9. Результаты проверки

**Исходное состояние (T001)**: pytest без ошибок, Vitest 52 теста, `npm run check` без ошибок.

**Замеры SC-003, живые сайты 2026-11-03**:

| Действие | Время |
|----------|-------|
| HDRezka: серия или озвучка | 0,4 с |
| KinoGo: серия, все узлы отвечают | 3–4 с |
| KinoGo: серия, есть недоступный узел | 11 с |

**Как проверено**:

- Настоящий backend по протоколу и живые сайты: KinoGo (`.io`, `.org`, `.tv`) и HDRezka. Потоки запускались в mpv без окна и звука.
- Настоящий интерфейс Svelte в скрытом Chrome с настоящим backend: выбор сезона и серии, смена озвучки, отмена, ближайшая серия, контрольный фильм. Запуск плеера подменён записью параметров.
- Автооткрытие: подбор и `open_movie` с настоящей HDRezka при подменённом отказе KinoGo; сообщение в интерфейсе по ответу с пометкой.

**Не проверено**: устаревшая ссылка спустя 30 минут (есть тест); сериал без группы сезонов на живом сайте (есть тест, у всех проверенных сериалов группа сезонов есть).

**Настоящее окно**: работу в окне Tauri с mpv подтвердил пользователь.

**Посторонний сбой**: узел `prx3-cogent.ukrtelcdn.net` у HDRezka иногда зависает. Разбор ссылок здесь ни при чём: запасной адрес `stream.voidboost.one` у той же серии играет, и приложение переключается на него само.
