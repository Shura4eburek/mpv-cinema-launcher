# Research: Новый интерфейс приложения и плеера

Статусы проверки: **проверено** — запускалось на машине разработчика; **по исходникам** —
прочитан код, но не запускалось; **не проверено** — нужна проверка в T001.

## R1. Интерфейс плеера: uosc 5.13.0

- **Decision**: включить в репозиторий `uosc` 5.13.0 (LGPL-2.1) и подключать его только
  из лаунчера через `--script`, не меняя глобальный конфиг mpv пользователя.
- **Rationale**: готовые таймлайн, автоскрытие, буферизация, меню дорожек и субтитров,
  перевод на русский (`intl/ru.json`). Покрывает FR-001…FR-004 без своей отрисовки.
- **Alternatives**: встроенный OSC — нет русского языка и меню; своя панель на Lua — большой
  объём работы; встраивание mpv в окно приложения — сложнее и отвергнуто в спецификации.
- **Статус**: проверено на тестовом видео (T002, запускал пользователь): загрузка из отдельного
  каталога, значки, русский текст, панель, своя кнопка в `controls`, `open-menu`, `close-menu`,
  `set-min-visibility`. На реальном потоке перемотка и дорожки ещё не проверены (T020).

## R2. Состав включаемых файлов uosc

- **Decision**: взять `scripts/uosc` без `bin/` и шрифты из `fonts/`, всего ~900 КБ, плюс текст
  лицензии.
- **Rationale**: `bin/` (17 МБ) содержит исполняемый `ziggy`, который нужен только для поиска
  субтитров в сети. Эта функция вне объёма. Бинарные файлы в репозитории не нужны.
- **Alternatives**: скачивать при первом запуске, как шейдеры — интерфейс зависел бы от сети.
- **Статус**: проверено (T002): без `bin/` запуск проходит без ошибок в логе.

## R3. Состояние и переключение апскейла

- **Decision**: собственный скрипт `cinema.lua`. «Работает» — в `vo-passes` есть проходы
  шейдера. «Не требуется» — шейдеры заданы, но проходов нет. «Выключен» — список
  `glsl-shaders` пуст. Переключение сохраняет и восстанавливает список в памяти скрипта.
- **Rationale**: `vo-passes` показывает фактический рендер, а не только настройку.
- **Статус**: проверено на FSRCNNX: «Работает» → «Выключен» → «Работает» без перезапуска;
  отсутствие проходов при масштабе 1:1 подтверждено ранее. Для Anime4K признак проходов — не
  проверено, уточняется при реализации.

## R4. Название и разрешение в плеере

- **Decision**: `--force-media-title=<название>`; разрешение читается из свойств `width` и
  `height`. Метка качества с сайта в плеер не передаётся.
- **Статус**: проверено на тестовом видео.

## R5. Технология приложения: Tauri 2 и Svelte

- **Decision**: Tauri 2.12 и Svelte 5 с TypeScript на Vite. Ветка 3.0 ещё в alpha и не используется.
- **Rationale**: выбор пользователя. Веб-интерфейс даёт анимации, наведение и адаптивную сетку.
  Svelte небольшой и достаточен для 4 экранов; вывод текста экранируется по умолчанию.
- **Alternatives**: CustomTkinter — нет нужного вида; Slint и egui — сложнее получить вид каталога;
  React — больше, чем нужно приложению такого размера.
- **Статус**: Rust 1.97, MSVC Build Tools 2022, Node 22 и WebView2 на машине есть. Сборка каркаса —
  не проверено (сквозной срез).

## R5a. Связь с Python: JSON Lines через stdin и stdout

- **Decision**: Rust запускает `python -m mpv_launcher.backend` (при разработке) или собранный
  backend (в установщике) и обменивается строками JSON. Протокол описан в
  [contracts/backend-protocol.md](./contracts/backend-protocol.md).
- **Rationale**: не открывает сетевой порт, а значит, к backend не могут обратиться другие программы
  на компьютере; нет лишних зависимостей; легко тестируется без окна.
- **Alternatives**: локальный HTTP-сервер — нужен порт и защита от других процессов; PyO3 —
  сложная сборка и привязка к версии Python.

## R5b. Упаковка backend: PyInstaller onedir в ресурсах Tauri

- **Decision**: собирать onedir и подключать через `bundle.resources`; путь определять через
  `BaseDirectory::Resource`, запускать через `std::process::Command` без окна консоли.
- **Rationale**: `externalBin` требует один файл, а onefile при каждом запуске распаковывается во
  временный каталог и замедляет старт. Плагин shell не нужен, что сокращает права интерфейса.
- **Статус**: механизм `bundle.resources` — по документации Tauri. PyInstaller 6.16 установлен.
  Работа Selenium Manager в сборке — не проверено.

## R6. Фоновые задачи в backend

- **Decision**: одна очередь для всех операций с Selenium, отдельные потоки для постеров и запуска
  mpv. Интерфейс отбрасывает ответы на устаревшие запросы по их номеру.
- **Rationale**: общий драйвер не потокобезопасен, а поздний ответ не должен перезаписывать новый
  экран. Просмотр фильма не должен блокировать поиск.

## R6a. Постеры

- **Decision**: backend скачивает постер в кэш и возвращает путь. Интерфейс показывает файл через
  протокол `asset`, а область доступа ограничена каталогом кэша.
- **Rationale**: запросы идут с теми же заголовками, что и сейчас, CSP может не разрешать внешние
  адреса, а повторное открытие выдачи получается мгновенным.

## R6b. Безопасность данных с сайта

- **Decision**: без `{@html}`; CSP `default-src 'self'`; без плагинов shell и fs. Backend принимает
  только адреса `http` и `https`, а поток для запуска проверяет через `url.validate`.
- **Rationale**: названия и описания приходят со стороннего сайта и зеркал. Команды приложения
  доступны всему окну по умолчанию, поэтому проверки должны быть на стороне backend.

## R7. Настройки

- **Decision**: JSON в каталоге настроек пользователя (`%APPDATA%\mpv-cinema-launcher` на
  Windows, `~/Library/Application Support/mpv-cinema-launcher` на macOS). Атомарная запись;
  при повреждённом файле используются значения по умолчанию.
- **Rationale**: только стандартная библиотека, легко тестируется.

## R8. Варианты качества картинки

- **Decision**: два варианта: «Максимальное» (`max`) и «Базовое» (`basic`). Вариант
  `balanced` убрать.
- **Rationale**: в `presets.py` `balanced` работает точно так же, как `max`, то есть выбор
  сейчас ничего не меняет.
