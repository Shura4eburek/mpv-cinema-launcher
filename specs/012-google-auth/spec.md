# Feature Specification: Вход через Google

**Feature Branch**: `012-google-auth`

**Created**: 2026-11-16

**Status**: Draft

**Input**: User description: "Вход через Google (issue #11, этап 1). Вход и выход Google-аккаунтом; вход через системный браузер с ответом на локальный адрес и PKCE, без client secret в репозитории; права openid, email, profile и drive.appdata (для этапа 3); refresh token в системном хранилище учётных данных; в Настройках блок «Аккаунт Google» (вход, аватар, имя, email, выход с отзывом токена); восстановление входа при запуске; понятные сообщения при отмене, таймауте и без сети; приложение работает без входа. Вне рамок: синхронизация через Google Drive."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Войти через Google (Priority: P1)

Пользователь открывает Настройки, в блоке «Аккаунт Google» нажимает «Войти через Google». Открывается системный браузер со страницей входа Google. Пользователь выбирает аккаунт и разрешает доступ. Браузер показывает «Вход выполнен, вернитесь в приложение», а в приложении блок показывает аватар, имя и email.

**Why this priority**: Без входа нельзя сделать синхронизацию (этап 3); это основа этапа.

**Independent Test**: Нажать «Войти через Google», пройти вход в браузере — в Настройках появились аватар, имя и email аккаунта.

**Acceptance Scenarios**:

1. **Given** пользователь не вошёл, **When** он нажимает «Войти через Google», **Then** открывается системный браузер со страницей входа Google, а кнопка в приложении показывает ожидание и кнопку «Отмена».
2. **Given** открыта страница входа, **When** пользователь разрешает доступ, **Then** в браузере страница «Вход выполнен, можно закрыть вкладку», в приложении — аватар, имя и email.
3. **Given** открыта страница входа, **When** пользователь отказывает в доступе, **Then** приложение показывает «Вход отменён», состояние «не вошёл».
4. **Given** идёт ожидание входа, **When** пользователь нажимает «Отмена» в приложении или проходит 5 минут, **Then** ожидание прекращается, показывается сообщение, можно начать вход заново.
5. **Given** нет сети, **When** пользователь пытается войти или завершить вход, **Then** приложение показывает «Нет связи с Google», ничего не ломается.

---

### User Story 2 - Вход сохраняется между запусками (Priority: P2)

Пользователь, вошедший ранее, запускает приложение — в Настройках он по-прежнему вошёл, повторно вводить ничего не нужно.

**Why this priority**: Без этого вход пришлось бы повторять каждый запуск.

**Independent Test**: Войти, закрыть и снова открыть приложение — в Настройках тот же аккаунт без повторного входа.

**Acceptance Scenarios**:

1. **Given** пользователь вошёл, **When** приложение перезапущено, **Then** в Настройках тот же аккаунт без открытия браузера.
2. **Given** доступ отозван в настройках Google-аккаунта или срок истёк, **When** приложение запущено, **Then** блок показывает «Нужно войти заново» и кнопку «Войти через Google».
3. **Given** пользователь вошёл и нет сети, **When** приложение запущено, **Then** показывается последний известный аккаунт с пометкой «нет связи», вход не сбрасывается.
4. **Given** пользователь вошёл, **When** проверяют файлы настроек приложения, **Then** в них нет секретов доступа — только в системном хранилище учётных данных.

---

### User Story 3 - Выйти из аккаунта (Priority: P3)

Пользователь нажимает «Выйти» — приложение забывает аккаунт и отзывает выданный доступ.

**Why this priority**: Нужно для смены аккаунта и приватности, но реже основного сценария.

**Independent Test**: Нажать «Выйти» — блок снова показывает «Войти через Google»; после перезапуска пользователь не вошёл; в списке приложений Google-аккаунта доступ отозван.

**Acceptance Scenarios**:

1. **Given** пользователь вошёл, **When** он нажимает «Выйти», **Then** блок показывает «Войти через Google», сохранённый доступ удалён из системного хранилища, Google получает запрос на отзыв.
2. **Given** нет сети, **When** пользователь нажимает «Выйти», **Then** локальный выход выполняется всё равно, пользователю сообщается, что отозвать доступ в Google не удалось.

---

### Edge Cases

- Пользователь закрыл вкладку браузера, не завершив вход: приложение ждёт до отмены или таймаута.
- Повторное нажатие «Войти» во время ожидания: новое ожидание не запускается, старое продолжается.
- В браузере открыт ответ от чужой или устаревшей попытки входа: ответ отклоняется, вход не выполняется.
- Системное хранилище учётных данных недоступно: вход работает до закрытия приложения, показывается предупреждение «вход не сохранится».
- Аккаунт без аватара: показываются инициалы.
- Приложение работает без входа: поиск, просмотр, «Мой список» работают как раньше, вход нигде не требуется.
- Приложение собрано без настроенного идентификатора Google-клиента: кнопка входа недоступна с пояснением.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: В Настройках MUST быть блок «Аккаунт Google»: в состоянии «не вошёл» — кнопка «Войти через Google»; после входа — аватар (или инициалы), имя, email и кнопка «Выйти».
- **FR-002**: Вход MUST выполняться в системном браузере пользователя; приложение принимает ответ Google на своём компьютере и не просит вводить пароль в своём окне.
- **FR-003**: Вход MUST быть защищён от подмены ответа: ответ без совпадающей проверки текущей попытки отклоняется.
- **FR-004**: Приложение MUST запрашивать только права: имя, email, аватар и доступ к собственной скрытой папке приложения в Google Drive (для будущей синхронизации). Доступа к остальным файлам Drive оно не запрашивает.
- **FR-005**: Секреты доступа MUST храниться только в системном хранилище учётных данных (Windows Credential Manager, Связка ключей macOS); в файлах настроек и в репозитории их нет.
- **FR-006**: При запуске приложение MUST восстанавливать вход по сохранённому доступу без открытия браузера.
- **FR-007**: Если сохранённый доступ отозван или недействителен, приложение MUST показывать «Нужно войти заново» и удалять недействительный доступ.
- **FR-008**: «Выйти» MUST удалять сохранённый доступ и отправлять Google запрос на его отзыв; при неудаче отзыва локальный выход всё равно выполняется.
- **FR-009**: Ожидание входа MUST прекращаться по кнопке «Отмена» и через 5 минут; отказ в доступе, таймаут, отсутствие сети показываются понятным сообщением на русском.
- **FR-010**: Все функции приложения MUST работать без входа так же, как до этого этапа.
- **FR-011**: Нажатие «Войти» во время идущего входа MUST не запускать вторую попытку.
- **FR-012**: Если системное хранилище недоступно, вход MUST работать до закрытия приложения с предупреждением, что он не сохранится.

### Key Entities

- **Аккаунт**: имя, email, адрес аватара — показываются в Настройках; хранятся рядом с настройками только для показа без сети.
- **Сохранённый доступ**: долгоживущий секрет для получения доступа без повторного входа; только в системном хранилище.
- **Попытка входа**: текущее ожидание ответа из браузера; одна за раз, с таймаутом 5 минут.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Вход с уже выбранным в браузере Google-аккаунтом занимает не больше 3 кликов и 30 секунд.
- **SC-002**: После перезапуска вошедший пользователь видит свой аккаунт в Настройках в течение 3 секунд без действий.
- **SC-003**: Ни в одном файле приложения и репозитория нет секретов доступа (проверка поиском по файлам после входа).
- **SC-004**: Отмена, отказ, таймаут и отсутствие сети в 100% случаев заканчиваются понятным сообщением и рабочим приложением.
- **SC-005**: Без входа все сценарии предыдущих этапов проходят без изменений.

## Assumptions

- Идентификатор Google-клиента типа «Настольное приложение» заводит владелец проекта в Google Cloud Console и передаёт приложению при сборке; если Google требует секрет клиента для настольного типа, он считается не секретным (по документации Google) и тоже передаётся при сборке, но не хранится в репозитории.
- Пока приложение в режиме тестирования Google, войти могут только аккаунты из списка тестировщиков; публикация и проверка приложения в Google — вне рамок.
- Один аккаунт за раз; переключение — через «Выйти» и новый вход.
- Синхронизация «Моего списка» через Google Drive — этап 3, вне рамок; здесь только получение права на неё.
- Аватар загружается из сети; без сети показываются инициалы.
